\section{Failures That Present as Success}
\label{sec:silent}

In an evaluation pipeline the dangerous failure is not the one that crashes.
It is the one that returns a number. A crash gets fixed within the hour; a
pipeline that reports \texttt{30/30 exit=0} while having measured nothing gets
written into a table, and then into a paper.

We hit this six times. Every instance was found after results based on it had
already been reported, and none was visible from inside the pipeline. We
document them as a class rather than as a list of bugs, because the shape
repeats and the defences generalise.

Two are platform translations that silence a component without an error. Git
for Windows rewrites shell scripts to CRLF on clone, so the entrypoint shebang
becomes \texttt{bash\textbackslash r} and the container exits 127. The egress
proxy is the only service that boots through a script, so it never starts,
taking two of the three monitors with it; the third survives because the
compose file gives it an explicit entrypoint, which is exactly why the failure
looks partial rather than total. Separately, MSYS rewrites POSIX-looking
arguments before \texttt{docker.exe} sees them, so the container exits 2 and
\texttt{-{}-rm} removes it before anyone can read the log. The sweep then
reports ``not detected'', which reads as a slow monitor rather than a
container that never ran.

Three are configurations pointing somewhere other than intended. The promptfoo
provider exported \texttt{TASK\_FILE} and \texttt{HARNESS\_CONDITION} where
the compose file reads \texttt{TASK} and \texttt{CONDITION}, so every
evaluation ran the default task and ignored the generated payload while
returning transcripts. The positive-control suite brought up the filesystem
monitor without \texttt{-{}-no-deps}, pulling in the real sandbox, which runs
its own heartbeat under the same run identifier: the heartbeat control passed
in 1.8 seconds having timed the sandbox's clean shutdown rather than the
pinger it kills. It was caught because the suite was quietly spending paid API
quota on agent runs it was documented not to need. And when the model backend
went down mid-session, the agent caught the error, wrote it to the transcript
and ended its loop, so thirty runs reported success with zero tool calls
between them.

The sixth reached the published numbers. The attacker logs each delivery of
its payload, and counting those against runs shows eight of twenty were never
served the attack, skewed by condition. In the summary a run that was never
attacked is indistinguishable from one where the agent read the payload and
declined: both simply score low. That channel's rate had been computed over
planned runs rather than exposed ones.

\subsection{What we changed}

The common thread is that silence was being read as ``nothing to report''. The
defences all make components prove they were alive.

\begin{itemize}
\item Each monitor emits a startup event naming itself and its configuration,
      so a monitor that never booted is distinguishable from one with nothing
      to say. The egress monitor also reports whether its baseline is empty,
      since an empty baseline marks every destination anomalous and makes one
      control incapable of failing.
\item The test scripts check that the Docker daemon answers before doing
      anything, and exit with a distinct code so ``Docker is down'' cannot be
      confused with ``a control failed''.
\item The orchestrator inspects each finished run, records the diagnosis in
      that run's metadata, and prints how many produced no data. It caught an
      empty run on its first outing.
\item The analysis tolerates a torn log line and names the file and line
      rather than dying, because the three monitors append to one file from
      separate containers and that append is not atomic over a bind mount.
      A lost line may be an inert event or an alert that changes a verdict.
\item Every figure is counted over the artifacts at the time of writing, never
      read from the configuration that would have produced them. One retracted
      table was written from \texttt{repetitions: 10} in a YAML file while
      three runs existed on disk.
\end{itemize}
