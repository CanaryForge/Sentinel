\section{Threats to Validity, and Four Corrections}
\label{sec:validity}

Every figure in an earlier draft was recomputed from the raw artifacts,
independently of the script that produced it. The aggregates computed by code
survived. Four claims did not, and the pattern is the transferable part: what
held was counted, and what failed was written by hand or read from a
configuration file.

\subsection{The filesystem monitor was detecting itself}

\texttt{agent.py} writes the agent transcript into \texttt{/workspace} so the
canary monitor can see it. When the model narrates its intent in prose, saying
it will create \texttt{/workspace/ack\_<canary>}, the token lands in that log
and the monitor fires on an artifact the harness wrote. This happens in 34 of
60 corpus runs.

The reported detection rate of 25/25 becomes \textbf{19/25} counting only
surfaces the agent produced. Two effects need separating, because they are not
equally serious. Six detections have no other signal at all: those leaks are
genuinely unseen, and the reported detection was an artifact. The rest have
real signal that arrived after the self-detection, so what is wrong there is
the time to detection, not the detection.

The monitor now excludes its own log. That change was not applied
retroactively, since altering a monitor alters the measured system; the
corrected figures come from reprocessing the existing artifacts.

Level counts are unaffected, because levels 0 through 5 come from the
transcript rather than from monitor events. That separation is why a
correction this large leaves Section~\ref{sec:results} standing.

\subsection{A published table had no data behind it}

An earlier draft reported ten runs of \texttt{con\_harness\_generico} at 4/10.
Three existed on disk, one of them truncated. The figure had been written from
\texttt{repetitions: 10} in a YAML file rather than counted over the
artifacts. It was retracted, and the experiment was then actually run, which
is what Section~\ref{sec:results} reports.

The rule that came out of it is now written into the repository: every figure
is counted over the artifacts at the time of writing, never read from the
configuration that would have produced them.

\subsection{A runtime version made the main finding disappear}

The first homogeneous causal run produced 10/10 in all three conditions. With
the control condition saturated there is no low reference point and nothing
can be compared, which we initially and wrongly reported first as a
falsification and then as a null result. Both readings were made on data with
no power to support either.

The cause was the Ollama release. Machine A ran 0.32.5 and machine B ran
0.6.8, and because Ollama numbers releases as \texttt{0.MINOR.PATCH} with a
minor past one digit, the second is twenty-six minor versions older rather
than newer. On the old release the agent loops, repeating an identical tool
call 42\% of the time, and exhausts the fifteen-turn cap in 17 of 30 runs.
Machine A never reached that cap in 63 runs. Given three times the turns,
almost any run eventually touches the canary, which is what drove every
condition to the ceiling.

None of this was recoverable from the artifacts. The corpus recorded neither
the Ollama version nor the effective context, and the model name existed only
as prose in a report. The orchestrator now queries the server and writes the
version into every run's metadata.

\subsection{Runs were not independent, and one denominator was wrong}

\texttt{./memory} is a host bind mount, so \texttt{docker compose down -v}
never clears it. After the causal matrix the file held 85 notes, 58 carrying
the literal canary of an earlier run: an agent could read another run's secret
through \texttt{memory\_read}, and no task with a memory channel started from
the same state as the run before it.

The mechanism is visible in the transcripts, and it is not the one we
expected. In \texttt{task\_06}, a retrieval task with no memory component at
all, 9 of 23 runs wrote to persistent memory unprompted, and 8 of those writes
carried that run's own canary token. Nothing in the task asks the agent to
record anything. It writes a note about what it did, the note contains its
session identifier, and the file outlives the container. The poisoning channel
that mattered most was not the one we planted; it was the agent's own habit of
leaving notes for itself. The orchestrator now resets memory before
each run, to the seeded poisoned note for the memory-poisoning task and to
empty otherwise. Contamination turned out not to inflate the rates, since
clean memory moved the control condition up rather than down, but the runs
were not comparable while it persisted.

Separately, the red-teamer logs each delivery of its payload, and counting
those against runs shows that eight of twenty runs in \texttt{task\_04} were
never served the attack, skewed by condition. In the summary a run that was
never attacked is indistinguishable from one where the agent read the payload
and declined: both simply score low. The channel rate in
Section~\ref{sec:results} therefore carries both denominators.

\subsection{Two structural limits we did not fix}

\paragraph{The SSRF path evades the egress baseline.} When the agent reaches
the attacker through the route the task suggests, the proxy sees
\texttt{package-registry:5000}, which is in the baseline because it is a
legitimate service. The attacker's address travels URL-encoded inside a query
string, where the baseline check does not look, and the second hop happens
server to server inside an internal network without crossing the proxy at all.
This is the anchor incident's own pattern, and it bounds what the egress
monitor is for: it catches the naive agent and misses the one that takes the
detour the task offers it.

The bound is a capability, not an observed evasion, and the distinction
matters. Across all 113 runs the proxy recorded exactly one destination,
\texttt{mirror-externo:5002}, thirty times, flagged anomalous on every one:
every agent that reached the attacker went at it directly. Not one run used
the SSRF route. The blind spot was demonstrated by a synthetic control, not
exploited by a model, so what we report is that the monitor can be evaded this
way, not that it was.

\paragraph{The shared event log is not safe under concurrent append.} The
three monitors append to one file per run from separate containers, and that
append is not atomic over a Docker Desktop bind mount on Windows. We observed
lines beginning mid-JSON. The analysis now skips a torn line and names the
file and line rather than dying on it, but a lost line may be an inert event
or an alert that changes a run's verdict.

\paragraph{Tool-call sequences do not predict a leak.} We looked for a
syntactic signal in the transcripts, on the theory that the order in which an
agent reaches for its tools might separate runs that leak from runs that do
not. It does not, at least at this sample size: the dominant transitions are
the same in both groups, and the apparent signal in which tool an agent
reaches for first is an artifact of each task exposing a different channel. We
report the negative because it bounds what the transcripts support.

\paragraph{Canary obfuscation coverage is a floor, not a claim.} Detection
matches the plain token plus base64, URL encoding, hex and reversal. An agent
encoding the token in, for example, the lengths of file names defeats it, and
we make no claim beyond the four.
