\section{Reproducibility}
\label{sec:repro}

\subsection{The data is in the repository}

All 416 runs are versioned in the repository~\cite{sentinel-repo}, 7.9\,MB
across 1415 files: per-run metadata, monitor events, and full agent
transcripts, plus the aggregate files and the 35 excluded runs, which are
kept rather than deleted. They cost real API quota and cannot be reproduced
identically, which is why they are committed rather than regenerated. Every
table in this paper can therefore be recomputed by a reader without a model
backend and without spending anything:

\begin{lstlisting}[language=bash]
python3 analysis/compute_ttd.py                    # corpus, 70 runs
python3 analysis/compute_ttd.py --results-dir \
        results/machine-B/causal-ollama0.34.0     # causal, 30 runs
python3 analysis/compute_ttd.py --results-dir \
        results/machine-B/redteam-ollama0.6.8     # task_04, 20 runs
python3 analysis/compute_ttd.py --results-dir \
        results/machine-D/corpus                  # tasks 04-06, 33 of 60 runs
python3 analysis/compute_ttd.py --results-dir \
        results/machine-D/memory-rag-run2         # tasks 05-06 repeat, 32 of 40 runs
\end{lstlisting}

\subsection{Running the harness}

Ordered cheapest first. Everything except the last step runs without a model
backend.

\begin{lstlisting}[language=bash]
docker compose config -q                                    # compose validates
python3 orchestrator/run_experiment.py --dry-run --limit 5   # matrix expands
tests/positive_controls.sh                                   # 6 controls, ~4 min
python3 analysis/compute_ttd.py                              # reproduces the tables
python3 timeline/export_timeline.py                          # forensic timeline
tests/monitor_strength_sweep.sh                              # parameter sweep, ~7 min
python3 orchestrator/run_experiment.py                       # the matrix (needs a backend)
\end{lstlisting}

If any positive control fails, do not report detection rates. That is the
whole point of the suite.

\subsection{Environment traps}

Three of these cost us a working day each, and all three are invisible until
something downstream is already wrong. They are listed here so the next team
does not pay for them again.

\begin{itemize}
\item \textbf{Line endings on Windows.} Git for Windows rewrites shell scripts
      to CRLF on clone, which turns the entrypoint shebang into
      \texttt{bash\textbackslash r}. The egress proxy is the only service that
      boots through a script, so it never starts, and two of the three monitors
      go silent with no visible error. A \texttt{.gitattributes} pinning
      \texttt{eol=lf} fixes it for every clone.
\item \textbf{Path translation under Git Bash.} MSYS rewrites any
      POSIX-looking argument before \texttt{docker.exe} sees it, so
      \texttt{/app/heartbeat.py} arrives as a Windows path, the container exits
      2, and \texttt{--rm} deletes the evidence. \texttt{MSYS\_NO\_PATHCONV=1}
      fixes it. The orchestrator is unaffected, since it passes no POSIX paths
      to the Docker CLI.
\item \textbf{Ingestion age limits.} The timeline exporter targets OpenObserve,
      which discards events older than five hours by default and reports it as
      HTTP 200 with a failure count in the body. A forensic timeline is old
      data by definition.
\end{itemize}

versioned corpus above. Machine D is the first Windows-on-ARM host in the
project and, unlike C, ran the local model: 35 of its 100 runs (task\_04
through 06, same runtime as B's valid batch) came back with
\texttt{docker\_exit\_code=0} and zero tool calls, because
\texttt{sandbox/agent.py}'s fixed 120\,s client timeout is shorter than the
prompt-evaluation time this CPU needs for the harness's own system prompt.
Replaying that exact first-turn payload against the local server measured
109.0\,s of prompt evaluation plus 3.9\,s of generation, five seconds under
the timeout, with the model already resident (load time 15\,ms): not a cold
start, just a CPU too slow for a client timeout tuned on faster hardware.
Three of the affected runs were individually re-launched as a check and
failed identically each time, so this is a standing property of the
machine, not a one-off stall. Those 35 runs were moved to sibling
\texttt{*-invalidas-timeout} directories with their own manifest rather than
deleted, and are excluded from every count in this paper; the 65 that remain
are reported in Sections~\ref{sec:results} and~\ref{sec:suspected-compromise}.}
