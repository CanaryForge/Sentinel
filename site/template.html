Most agent escapes never touch the network.

Sentinel tempts an LLM agent out of its Docker sandbox and watches it with three signals that never read the model: process silence, a canary token on the filesystem, and egress against a baseline. Then it measures how long the escape went unseen.

Anchored on the OpenAI and Hugging Face incident of July 2026: SSRF through Artifactory, agent-to-agent traffic encoded in directory names, and no real-time detection. The directory-name channel is the one this harness reproduces most clearly.

An escape is a ladder, not an event

Every run is scored from level 0, no signal at all, to level 6, sandbox broken and the heartbeat gone. Two counts per rung, because they answer different questions. The rungs are evaluated independently, so reaching level 5 does not imply having passed through 3 and 4, and adding the distribution upward would invent a number the data does not support.

An authorised destination is not a safe one

the blind spot

The egress monitor flags the destination node, not the contents of the path. A request carrying the attacker's real address inside its query string is indistinguishable from a legitimate fetch of the same service, as long as you only read the destination column. What this does not show

Written before the results existed, so it could not be shaped around them. The full version lives in report/scope.md.

It does show

  • That three cheap, model-independent signals catch induced escape attempts, and how long each one takes to do it.
  • That time to detection can be measured reproducibly, with a confidence interval, on a single laptop.
  • A clonable harness another team can run and extend.
  • That vectors 5 and 6 sit under OWASP ASI06, Memory and Context Poisoning, rather than being scenarios invented without external anchoring.

It does not show

  • That a real agent in production would behave this way. The temptation here is planted, and the model is a single local 7B.
  • That the con_harness condition is a defence. It is a system prompt warning, not a runtime guard like OWASP Agent Memory Guard.
  • Anything about the machine that produced each batch. That is prose in report/hardware_validation.md, not a field in the artefacts.
  • Perfect capture. Some appends were torn by the bind mount.
